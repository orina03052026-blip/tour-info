## Googleカレンダー運用ルール

### 1. 勤務登録イベント（タイトルで判定）

タイトルにスタッフ名＋記号＋時間を書く。Googleカレンダー側は**固定表記（砂川 / 畑中）**を使う。
スプレッドシート側の表記（Sho / Kana）は aliases で対応している。

- 出勤例: `砂川〇 09:30-18:00` / `畑中〇 09:30-14:00`
- 休み例（終日）: `砂川✖` / `畑中✖`（終日Off。all-day予定で作る）
- 休み例（時間付き）: `砂川✖ 9:30-13:00`
  → その時間に重なる枠だけOff、重ならない枠はAvailable。
  例: `9:30-13:00` なら AM=Off（09:30-12:30に重なる）/ PM=Available（13:30以降は空き）。
  時間はカレンダーの予定時刻でも、タイトルに `9:30-13:00` と書いてもOK（区切りは - ~ 〜 – いずれも可）。

記号（`sync_availability.gs` CONFIG）:
- AVAILABLE: `〇 ○ ◯ ⭕ 🟢 ✅ ✔ OK`
- OFF: `× ✖ ✕ ✗ ❌ ❎ X 休み OFF`

### 2. 予約済みイベント（説明欄＝descriptionで判定）

タイトルは自由。**説明欄に参加スタッフ名**を書く。

説明欄例:
```
参加スタッフ：
砂川、畑中
```

説明欄にスタッフ名が含まれていれば、そのイベント時間に重なる枠で該当スタッフを **Off（予約済み）** にする。
名前が無いイベントは無視する。

## 判定優先順位

1. Manual Lock = TRUE → 一切変更しない
2. ✖ / OFF → 終日 Off
3. 予約済みイベント重複（説明欄に参加スタッフ）→ 該当時間帯 Off
4. 勤務時間不足 → Off
5. 問題なし → Available

## 判定ルール

- **勤務時間判定**: スタッフ終了時刻 >= ツアー終了時刻 なら Available、それ以外 Off。
  - AM のツアー終了時刻 = 12:00、PM = 17:00（`CONFIG.slotWindows[*].tourEnd`）。
- **重複判定式**: `eventStart < tourEnd AND eventEnd > tourStart`
- **AM/PM ウィンドウ（重複判定用）**: AM 09:30–12:30 / PM 13:30–17:00

> 補足: PMツアーが実際には 14:00-15:00 のように早く終わる場合、ノート上は
> 「15:00まで勤務でAvailable」が理想だが、現状コードはツアーごとの所要時間表を
> 持たないため PM は一律 17:00 基準（保守的）。短いツアーを個別判定したい場合は
> ツアー名→所要時間の表を CONFIG に追加して拡張する。

## 必須ヘッダ（変更すると停止する）

```
Date | Staff | Time Slot | Status | Tour | Booked | Capacity | Notes | Source | Manual Lock
```

## 初回セットアップ手順

1. スプレッドシート（`1Lyl_...`）を開く → 拡張機能 > Apps Script
2. `apps_script/sync_availability.gs` を全文コピペ → 保存
3. 関数 `setupSheets` を一度実行（ヘッダ・入力規則を作成）→ 権限承認
4. 関数 `syncAvailability` を実行 → 権限承認 → Availability シートに行が埋まることを確認

## Trigger（自動実行）整理方法

- 関数 `setupTrigger` を1回実行すると、`syncAvailability` の時間トリガーを作り直す。
  - スケジュール: **毎日 6時 / 7時 / 8時 / 9時 / 18時 / 0時(24時) の6回**（タイムゾーン Asia/Tokyo）。
  - 各トリガーは指定時刻の「その時間帯の中」で起動する（分単位ぴったりではない、Apps Scriptの仕様）。
  - スケジュールを変えたいときは `setupTrigger` 内の `hours` 配列を編集 → 再実行。
- 旧 `fill_missing_dates` / `fillMissingDatesDaily` のトリガーは削除してよい
  （左メニュー「トリガー」→ 不要な行のゴミ箱）。
- 1時間ごと等の古い `syncAvailability` トリガーは `setupTrigger` 実行時に自動削除される。

## 読み込み日数（syncDays）

- `CONFIG.syncDays = 15`（今日〜15日先まで Availability シートに書き込む）。
- 期間を変えたいときはこの数値を変更。

## Logs（実行ログ）確認方法

- Apps Script エディタ左メニュー「実行数（Executions）」で各実行の成否・ログを確認。
- 既知の無害ログ: `Tour could not be detected: レンタサイクル...`（Bokun以外の普通の予定が
  パース対象になっただけで、行構築は止まらない）。

## 運用上の注意

- シート共有が崩れると HP にデータが出ない →「リンクを知っている全員（閲覧者）」必須
- `/export?format=csv&gid=0` を使う（「ウェブに公開」CSVは最大5分キャッシュされるため不可）
- Googleカレンダーの共有権限変更時は取得失敗の可能性あり
- カレンダーは固定表記（砂川 / 畑中）を使う
